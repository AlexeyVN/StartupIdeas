# LinenTrack — MVP (одна страница, HTML/CSS/JS)

Единая веб-система гостиницы, которая отвечает на три вопроса:
**где** находится бельё и вещи номера, **кто и когда** изменил их количество
или состояние, **почему** возникло расхождение.

## Как запустить

Открыть `index.html` в браузере — всё работает офлайн, без сборки и сервера.

```bash
python3 -m http.server 8000   # либо просто открыть index.html двойным кликом
```

Данные хранятся в localStorage; демо-данные загружаются при первом запуске
(кнопка «Сбросить демо-данные» в шапке).

```

```

## Роли и экраны

| Роль            | Устройство        | Экраны                                             |
|-----------------|-------------------|----------------------------------------------------|
| Горничная       | телефон/планшет   | «Мой номер»: приёмка/сдача белья, фото, Offline    |
| Администратор   | компьютер         | Склад: приёмка из прачечной, выдача, заселение/выезд, контроль расхождений |
| Менеджер        | компьютер         | Аналитика: движение по лотам, журнал аудита, отчёты причин, нормы |

Вход выбирается на странице (демо-пользователи), дальше интерфейс подстраивается
под роль и ширину экрана.

## Данные MVP

* **lot** — единица учёта: тип (полотенце/простыня/…), инвентарный QR-код,
  состояние (`ok`, `dirty`, `laundry`, `damaged`, `written_off`, `missing`),
  локация (`room:101`, `linen_closet`, `laundry_vendor`, …).
* **movement** — перемещение лота: откуда → куда, кем, когда, причина
  (обязательна для списаний и расхождений).
* **audit_entry** — append-only запись: кто, когда, устройство, поле, было → стало.
* **reconciliation** — сверка норматива номера с фактом; каждая позиция расхождения
  требует причину, иначе не сохраняется.

## Что проверяет MVP

1. Таймлайн лота: где он сейчас и по каким локациям проходил.
2. Журнал: полная цепочка изменений количества/состояния с ФИО, временем и устройством.
3. Расхождение: список позиций без причины + последний держатель; сохранение
   невозможно без указания причины.
